## *Today* requirements left uncovered

- **SAFE-2**: engines only read. The fixture engine replaces the engine call (testing contract, *The fixture engine*), so the arguments Claude Code or Codex would be spawned with are not observable from any contract surface.
- **SAFE-5**: Windows, macOS and Linux; Node 20.19 or newer. A run of the suite is on one system and one Node, and no surface reports the platform. The checks that differ by platform compare resolved paths (case-insensitively where the disk ignores case); none holds on one system only, so no title carries a system tag.

## Contract gaps found while rewriting

1. **The writing window of a draw cannot be reached.** The join refusal `The draw is writing its file: start a new one once it has finished` (JOB-4) and "a cancel asked once the run is writing changes nothing" have no test switch that holds a draw in `writing`; reaching them needs a clock race. Listed as unit-test work.
2. **Where the stale-token sentence shows.** The ui contract says a mutating call refused for its token shows `The server restarted — reload the page`, but names no test id for it. H16 looks for the sentence on the page and for `save-retry`.
3. **A checkbox card's state has no named attribute.** `focus-whole`, `focus-option`, `focus-typed` and the destination cards are a checkbox or a radio card, but the contract does not say whether the test id is on the input or on a wrapper, nor how ticked and disabled read on a wrapper. The suite reads the element or the input it wraps (`isChecked`, `isDisabled`).
4. **`[fixture:overlong]` in a draw's typed choice.** The testing contract's *Draw* list says it acts on the overview call; its general marker list says "post and story, and a draw's overview". Whether the draw's channel call is lengthened too is unclear; H19 accepts one `Shortened` warning per text that needed a repair turn.
5. **`archdrawer migrate` on an `@4` file holding a presentation channel.** Resolved after RUN-1: the drawing contract's *Reading a `presentation` channel* now has migrate drop the channel only from an `@3`, `@2` or `@1` file. H35 uses `archdrawer open`, which writes an `@4` file back without it.
6. **The order of a `PUT`'s 409 and 400 checks** for a body that is both stale and invalid is not stated. H28 sends a valid body.
7. **`library-item-kinds` dots are "titled with the kind's name"**: a `title` attribute or an SVG `<title>` is not said. H02 counts elements with a `title` attribute.
8. **Folder-name markers on Windows.** A folder name cannot hold `[`, `:` or `]` there, so the fixture's folder markers (*Scan*, *Draw*) are reachable on Windows only through a typed choice's text or a test link's dashed repository name. The suite uses those two, so no scenario is tied to one system.
9. **"The one blue" (HOME-11)** and the contrast ratios of `library-item` point at DESIGN.md, which this author was not given; no colour is asserted.
10. **A story route's ignored changes on the overview.** The testing contract's *Routing* says a content change in it "is then ignored with one warning"; the api contract's *Routing* says each new part or connection is ignored "with one warning each". The fixture's `add` makes a part and a connection, so the two read as one or two warnings. RUN-1 shows two; H26 follows the api contract.
11. **Tab through radio cards.** The ui contract's *The keyboard* lists "the destinations" in the Tab order and calls them radio cards; as radios, the group is one Tab stop and the arrow keys move within it. H03 reaches the group by Tab and the README card by the arrow keys.
